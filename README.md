# athenafung1.github.io

Personal portfolio site for Athena Fung.

**Live at: https://athenafung1.github.io**

Built with [Astro](https://astro.build) as a static site. Pages are plain HTML at runtime; the
only JavaScript is a small theme/easter-egg script and, on the Fun page, a Svelte island for the
interactive piece.

## Repository layout

| Path | Purpose |
| --- | --- |
| `src/` | Site source: pages, layouts, components, styles, content and pure logic (`src/lib/`). |
| `public/` | Static files copied as-is: resume, sharing images, favicon, legacy redirect pages. |
| `dist/` | **Build output. The only directory GitHub Pages serves.** Generated by `npm run build`; git-ignored; never edit it by hand. |
| `site/` | The previous hand-written site. Kept as a frozen record; no longer published, never edited. |
| `archive/` | Frozen snapshots of earlier versions. Never published. |
| `tests/unit/` | Vitest unit tests for everything in `src/lib/`. |
| `scripts/` | `check-content.mjs` (post-build content gate) and `render-og.mjs` (sharing images). |
| `.github/workflows/` | `pages.yml` (the one deploy path) and `checks.yml` (pull-request gates). |
| `.specify/`, `specs/` | Spec Kit artifacts: the project constitution, feature spec, plan and tasks. |

## Local development

Requires Node.js 24 (Astro 7 needs ≥ 22.12). With [nvm](https://github.com/nvm-sh/nvm):

```sh
nvm use                    # reads .nvmrc
npm ci                     # install exact locked versions
npm run dev                # http://localhost:4321, live reload
npm test                   # unit tests
npm run check              # type-check .astro / .svelte / .ts
npm run build              # static output in dist/
npm run preview            # serve dist/ over HTTP to check the real build
node scripts/check-content.mjs   # placeholder, privacy, title and description gate
```

Always check the built site over HTTP (`npm run preview`), never by opening files directly.

## Deployment

Deployment happens through exactly one mechanism: the **`Deploy to GitHub Pages`** workflow in
`.github/workflows/pages.yml`. On every push to `master` it installs dependencies, runs the
unit tests, builds the site and uploads **only `dist/`**. Nothing else in the repository
(`site/`, `archive/`, `specs/`, `.specify/`) is ever published.

Pull requests run `.github/workflows/checks.yml`: type-check, unit tests, build, the content
gate, an internal link check and Lighthouse budgets (performance and accessibility ≥ 90, LCP
< 2.5 s, < 1 MB per page). Paste the Lighthouse report links into the pull request.

One-time setup required in the repository settings:

> Settings → Pages → Build and deployment → Source: **GitHub Actions**, and **Enforce HTTPS** on.

## Editing content

All content is plain YAML or Markdown, validated when the site builds. A missing or invalid
field stops the build with a message naming the file and field. Full formats and examples:
[`specs/001-portfolio-site/contracts/content.md`](specs/001-portfolio-site/contracts/content.md).

| To change… | Edit |
| --- | --- |
| Name, role line, strengths, bio, education, experience, skills, contact links | `src/data/profile.yaml` |
| The resume | Replace `public/resume.pdf` (public version: **no phone number or street address**) |
| Navigation | `src/data/nav.yaml` (the only place navigation is defined) |
| A project | `src/content/projects/<slug>.md` |
| An interest on the Fun page | `src/content/interests/<slug>.md` |

Any text starting with `DRAFT:` is a stand-in. `node scripts/check-content.mjs` fails while any
remains (including in the stand-in resume), so drafts can't be deployed.

### Adding a project

Create `src/content/projects/<slug>.md` with frontmatter `title`, `summary` (1–3 sentences),
`tech`, at least one entry in `links`, and `order`. Optional: `image` (with `alt`), `period`,
`featured: true` (shown first and on the landing page, up to three).

### Adding a project detail page

Set `detail: true` and `detailDescription` (50–160 characters) in the project's frontmatter, then
write the body with `## Problem`, `## Approach` and `## Outcome` sections, in that order, plus at
least one image or fenced code block. The page appears at `/projects/<slug>/` and the project
card links to it. No navigation change is needed.

### Adding an interest

Create `src/content/interests/<slug>.md` with `title`, `order` and an optional `category`,
`images` (stored next to the file, each with `alt`) and `links` (`video`, `audio`, `writing` or
`other`; links only, never embeds). The body is the write-up, 1–150 words.

### Adding a page

Two edits, nothing else:

1. Create `src/pages/<name>.astro`:

   ```astro
   ---
   import BaseLayout from '../layouts/BaseLayout.astro';
   ---

   <BaseLayout title="Talks · Athena Fung" description="Talks and presentations by Athena Fung, with slides and recordings where available.">
     <h1>Talks</h1>
     <!-- page content -->
   </BaseLayout>
   ```

   `title` must be unique (≤ 60 characters) and `description` 50–160 characters. Use exactly one
   `<h1>`. The layout supplies the header, navigation, theme toggle, footer, contact links and
   sharing tags.

2. Add one line to `src/data/nav.yaml`:

   ```yaml
   - { id: talks, label: Talks, href: /talks/, order: 5 }
   ```

Then `npm run build && npm run preview` to check it. A custom sharing image is optional: add
`src/assets/og/<name>.svg`, run `node scripts/render-og.mjs`, and pass `ogImage="/og/<name>.png"`
to `BaseLayout`.

### Interactive pieces and easter eggs

See [`specs/001-portfolio-site/contracts/components.md`](specs/001-portfolio-site/contracts/components.md).
Pieces are Svelte components in `src/islands/` placed on `/fun/` inside `PieceFrame` with a
build-time fallback. Easter eggs are registered in `src/scripts/eggs.ts`. Keep their maths in
`src/lib/` with unit tests.
